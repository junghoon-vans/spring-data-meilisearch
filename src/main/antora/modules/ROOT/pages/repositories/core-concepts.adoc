[[repositories.core-concepts]]
= Core Concepts

Spring Data Meilisearch supports the core Spring Data repository programming model, but its repository surface is intentionally narrower than stores such as JPA, MongoDB, Elasticsearch, or Redis.

The important distinction is that this module currently provides:

* repository bootstrap through `@EnableMeilisearchRepositories` and the XML namespace,
* a store-specific `MeilisearchRepository<T, ID>` base interface,
* CRUD and paging/sorting methods implemented by `SimpleMeilisearchRepository`,
* direct access to advanced search features through `MeilisearchOperations`.

Derived finder methods, repository `@Query` methods, and named-query-backed methods are unsupported and fail during repository bootstrap. Use `MeilisearchOperations` for custom searches.

[[repositories.core-concepts.repository-interface]]
== Repository Interface

`MeilisearchRepository<T, ID>` extends Spring Data `CrudRepository` and `PagingAndSortingRepository`.
That means the stable repository contract is the built-in CRUD plus sorting/paging methods defined by those interfaces.

[source,java]
----
import org.springframework.data.repository.CrudRepository;
import org.springframework.data.repository.NoRepositoryBean;
import org.springframework.data.repository.PagingAndSortingRepository;

@NoRepositoryBean
public interface MeilisearchRepository<T, ID>
        extends CrudRepository<T, ID>, PagingAndSortingRepository<T, ID> {
}
----

[[repositories.core-concepts.execution-model]]
== Execution Model

The default repository implementation delegates to `MeilisearchOperations`, but repository methods use different Meilisearch APIs:

* `findById(...)` and `existsById(...)` use direct document lookup; `findAllById(...)` uses native ID-list retrieval.
* `findAll()` lists all documents in one document-list request. Sorted `findAll(Sort)` counts first, then fetches up to that count in one sorted request; additions between those requests can be absent.
* Paged `findAll(Pageable)` uses search APIs. An unpaged `Pageable` uses document listing and bases its total on the retrieved documents.
* `count()` reads the total from a document-list request with a zero-document limit; it does not run a search.

Search-backed repository methods are subject to search settings such as `pagination.maxTotalHits`. Document-list reads are not capped by that setting, although `displayedAttributes` can restrict fields returned when a request does not specify fields.

[[repositories.core-concepts-when-to-use]]
== When to Use Repositories vs. Operations

Use repositories when you want Spring Data's familiar persistence model for:

* saving and deleting entities,
* id-based reads,
* simple collection reads,
* sorting and pageable access.

Use `MeilisearchOperations` when you need store-specific behavior such as:

* `BasicQuery`, `IndexQuery`, `FacetQuery`, or `SimilarQuery`,
* federated multi-search,
* facet metadata,
* index lifecycle management,
* runtime settings updates.

For the concrete store-specific rules and current limitations, see xref:repositories/meilisearch-repositories.adoc[Meilisearch Repositories] and xref:repositories/repository-queries.adoc[Repository Methods and Limitations].
